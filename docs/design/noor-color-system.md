# NOOR Color System

How the brand palette was derived, verified, and organized. See
`packages/ui/tokens/colors.ts` for the canonical values and
`docs/design/noor-accessibility-review.md` for the full contrast audit.

## Anchor sampling

Dominant-color binning (RGB values grouped into 12-unit bins, most
frequent bins per region, near-white background pixels excluded) over
each content region produced:

| Region | Dominant sampled colors |
|---|---|
| "N" left half (navy→blue) | `#00306C`, `#003C78`, `#004884` |
| "N" right half (teal→emerald) | `#008478`, `#00B490`, `#00C090` |
| Network graphic | `#00306C`, `#0060C0` |
| Wordmark "NOOR" | `#002448`, `#001848` |
| Descriptor text | `#0C6060`, `#0C6C6C` |
| Glow dot | `#00B484`, `#00C090` |

These raw samples cluster tightly around the mission's own supplied
reference anchors (Deep Navy `#032855`, Clinical Blue `#045092`, Primary
Teal `#078A88`, Emerald `#09B993`) but are not identical to them — the
raw samples' `R` channel trends toward `0` at gradient edges, a known
JPEG chroma-subsampling artifact, not a real design intent. **The
mission's supplied reference values were adopted as the final anchors**,
with this sampling pass serving as independent validation that they sit
inside the artwork's real color range, not as a replacement source of
truth (this is the explicit, documented adjustment the mission itself
asked for: "avoid overfitting to JPEG compression artifacts... choose
stable anchors").

## Scale generation

Each of the four primary hue families (`brandNavy`/`brandBlue`/
`brandTeal`/`brandEmerald`) has a 50–950 ramp generated by linearly
blending the 500-anchor toward white (steps 50–400) or toward a
near-black, slightly cool-tinted floor `rgb(10,14,18)` (steps 600–950) —
**not** raw HSL-lightness interpolation. An HSL ramp was tried first and
rejected: at high lightness it kept full saturation and produced
"neon" mid-tones (e.g. a raw HSL-ramped teal-300 came out `#77F8F6`,
an implausibly vivid cyan no real UI should use). Linear RGB blending
toward white naturally desaturates as it lightens, which is what a
usable tint scale actually needs. `brandCyan`/`brandSlate` are not full
forced ramps — only the concrete steps actually used exist, per the
mission's own "don't generate scale steps with no real use" guidance.

## Semantic slots vs. raw scales

Feature UI should always use the semantic Tailwind classes
(`bg-primary`, `text-ink`, `bg-accent-soft`, …), never `brand-navy-500`
directly — the semantic layer is what stays stable if a brand hue is
ever revisited. The raw `brandNavy`/`brandBlue`/`brandTeal`/
`brandEmerald`/`brandCyan`/`brandSlate` scales exist for brand-expression
surfaces only: the gradient, the design-system swatch page, and the
brand documentation itself.

## Contrast verification

Every fg/bg pairing actually used for text was checked against the WCAG
2.2 relative-luminance formula before being finalized. Headline results
(full table in `docs/design/noor-accessibility-review.md`):

| Pairing | Ratio | Passes |
|---|---|---|
| Clinical Blue (`primary`) on white | 8.18:1 | AA + AAA |
| White on Clinical Blue | 8.18:1 | AA + AAA |
| Deep Navy (`ink`) on white | 14.60:1 | AA + AAA |
| Primary Teal text (teal-700) on white | 7.67:1 | AA + AAA |
| Primary Teal (teal-500, non-text use only — focus ring/border/icon) on white | 4.20:1 | Passes the 3:1 non-text threshold; **not** used as body text on white |
| New status colors (`queued`/`retryScheduled`/`reprocessingRequired`/`ocrRequired`/`deadLettered`) fg/bg | 5.98–11.23:1 | AA + AAA |

The one deliberate rule this enforces: Primary Teal at its 500 anchor
(`#078A88`) is used for borders, icons, and the focus ring (3:1
threshold), never as text color directly on white. Anywhere teal *text*
appears on a light surface, the darker `accentActive`
(`brandTeal[700]`, `#085D5E`, 7.67:1) is used instead — see
`WorkspaceNav`'s active-item styling (`text-accent-active`, not
`text-accent`).
